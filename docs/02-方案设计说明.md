## 1. 设计输入

- 需求来源：`01-需求规格说明.md`（版本 v0.1，共 14 条）
- 硬件平台：黄山派 SF32LB525UC6，板型 `sf32lb52-lchspi-ulp`；SDK 版本 v2.5.1（课程统一）
- 关键约束：
  - 屏幕 1.85" 390×450，QSPI（CO5300），**TE/VSYNC 可用**；触摸 IC **FT6146**；背光 PWM（PWMT1 ch4）
  - 大核 SRAM 512KB、小核 64KB；PSRAM 8MB（OPI 144MHz）→ 帧缓冲放 PSRAM
  - 单帧 390×450×2B = **351KB**，双缓冲 **702KB**
  - 板载无 WiFi；本项目不联网
  - 不使用 LVGL（见 ADR-0001）；素材自制或免授权（见 ADR-0002）
  - 课程第 7-10 周仅 4 周可用于设计/实现/测试（见 `00` 的 C-04）

## 2. 总体架构

> 自绘方案：不引入 UI 框架，主循环自己做帧节拍，触摸事件带时间戳进入判定引擎。

```mermaid

    subgraph 输入
        TP[FT6146 触摸<br/>中断 PA41] -->|信号量唤醒| IN[input_touch<br/>读点+打时间戳]
    end
    subgraph 时间基准
        TE[LCD TE 信号] --> LOOP[game_loop 固定帧循环]
        TICK[sys tick 1ms] --> LOOP
    end
    subgraph 逻辑
        CHART[chart 谱面解析] --> JUDGE[judge 判定引擎]
        IN -->|事件队列| JUDGE
        JUDGE --> STATE[scene 场景状态机]
        STATE --> SCORE[计分 Combo/Acc]
    end
    subgraph 渲染
        STATE --> GFX[gfx 绘制原语]
        GFX --> FB[fb 双缓冲 390x450x2]

    subgraph 输出
        JUDGE -->|P1| AUD[audio MP3 时间基准]

    end
```

## 4. 接口设计

### 4.1 软件接口

| 接口 | 输入 | 输出 | 错误处理 | 说明 |
|---|---|---|---|---|
| `touch_pop_event(&ev)` | — | `0` 有事件 / `-1` 无 | 队列空返回 -1 | 事件含 `t_ms`（中断时刻的系统毫秒时间戳） |
| `judge_touch(lane, t_ms)` | 轨号、点击时刻 | 判定结果枚举 | 无待判音符返回 `JUDGE_NONE` | 找该轨最近的待判音符并判定（Perfect ≤±60ms / Good ≤±120ms）；**超出 ±120ms 时不命中也不消耗音符**，留给 `judge_tick` 判 MISS |
| `judge_tick(now_ms)` | 当前时刻 | 新增 MISS 数 | — | 把超时未判的音符置为 MISS、Combo 归零 |
| `judge_load(notes, n)` | 音符数组、个数 | `0` / `-1` | 超过 `JUDGE_MAX_NOTES`(256) 返回 -1 | 第 3 步由 `chart` 提供音符 |
| `judge_selftest()` / `judge_bulk_test(n)` | — | 失败用例数 | — | 板上自检（边界/一次一符/Combo/Acc/分轨）与批量判定测试（TC-003 的 ≥50 次已知时刻） |
| `chart_parse(text, len)` | 谱面文本 | 音符数 / 负错误码 | 行格式错误返回行号负值 | 格式 `时间戳ms 轨号(0-3)`，`#` 起注释 |
| `chart_load_builtin()` | — | 音符数 / 负错误码 | 同 `chart_parse` | 解析内置谱面并直接 `judge_load()`，供 PLAYING 使用 |
| `chart_summary(&out)` | — | 音符数、首/末音符时刻、轨道分布 | 未加载时返回 -1 | 供 selftest（REQ-007）与串口摘要打印（REQ-006） |
| `scene_init()` | — | — | — | 重置到 TITLE（上电即主界面，REQ-001） |
| `scene_update(now_ms)` | 当前毫秒时刻 | — | — | 每帧调用一次：出队触摸事件、按状态分派、调 `judge_tick`、判是否进结算 |
| `scene_render()` | — | — | — | 每帧调用一次：只写背缓冲，不提交 |
| `scene_current()` | — | 当前状态枚举 | — | 供 selftest 与串口打印 |
| `gfx_text(x, y, s, color, scale)` | 坐标、字符串、颜色、整数倍缩放 | — | 超出屏幕的字符自动裁剪 | 5×7 自制字模；支持 `0-9 A-Z` 与 `: . % / - + ( ) 空格`，小写自动转大写，其它字符显示为空格 |
| `selftest_startup()` | — | 失败节数 | — | **第 1~2 节**（谱面 + 判定），启动时立即输出；同时把失败数存为静态变量供最终汇总 |
| `selftest_frame_stats()` | — | — | — | **第 3 节**（帧率）+ **总结论**；由帧循环在上电约 `SELFTEST_FRAME_WINDOW` 帧后调一次（不能在启动时调，否则没有帧样本） |
| `judge_latency_add(lag_ms)` | 触摸中断到判定执行的延迟 | — | — | 由 `scene` 在每次成功判定后调用；只统计「触摸→判定」，不等于「触摸→画面翻转」 |
| `judge_latency_hist(&out, n)` / `judge_latency_p95_ms()` | — | 直方图桶 / P95 | 无样本时返回 0 | 桶边界见右侧：0-10 / 11-20 / 21-33 / 34-50 / 51-100 / 超过 100（单位 ms） |
| `loop_stats(&out)` | — | 帧数、平均/P95 帧间隔、超时帧数 | — | 供 selftest 与串口打印 |
| `fb_present()`（原 `fb_swap`） | — | — | — | **单缓冲**提交整屏并等 `tx_complete`（ADR-0003）；原「双缓冲交换」方案未采用 |
| `fb_flush_rect(x0,y0,x1,y1)` | 矩形坐标 | — | 越界自动裁剪；**非整宽区域退回整屏提交并只警告一次** | 预留的脏区提交接口，是否启用取决于 M3 音符密度压力测试结果 |

### 4.2 数据结构与状态机

```c
struct touch_ev { uint32_t t_ms; uint16_t x, y; };          /* 中断时刻打戳 */
struct note     { uint32_t hit_ms; uint8_t lane; uint8_t state; };
struct judge_stat { uint32_t perfect, good, miss; uint32_t combo, max_combo;
                    uint32_t score; uint32_t total; };
struct chart_info { uint32_t notes;        /* 音符数 */
                    uint32_t first_ms;     /* 首个音符时刻 */
                    uint32_t last_ms;      /* 末个音符时刻（用于判定“演奏总长”） */
                    uint32_t per_lane[4]; };  /* 各轨音符数 */
```

**谱面文本格式细则**（第 3 步实现时确定，原需求只写了“每行：时间戳ms 轨号”）：

| 规则 | 取值 | 理由 |
|---|---|---|
| 分隔符 | 时间戳与轨号之间用空白（空格或制表符），前后允许多余空白 | 手写谱面容易多敲空格 |
| 注释 | `#` 起到行尾均为注释；只有空白或只有注释的行跳过 | 便于给谱面分段加说明 |
| 时间戳 | 纯十进制数字，范围 0 到 3600000，单位 ms | 覆盖 1 小时，足够 P0 单曲 |
| 轨号 | 只能是 0、1、2、3 | 4 轨固定（REQ-002） |
| **时间戳必须单调不减** | 违反时报错并返回该行行号 | `judge_touch` 依赖“找该轨最近的待判音符”，乱序会让判定错乱；错误要在加载时就暴露，不能留到演奏中 |
| 错误返回 | `-(行号)`，行号从 1 起算；成功返回音符数 | 与 TC-006 “错误谱面输出具体行号错误”对齐 |
| 音符上限 | 256（= `JUDGE_MAX_NOTES`） | 音符池固定上限，不动态分配（REQ-102） |

**演奏参数**（第 3 步新增）：

| 参数 | 取值 | 说明 |
|---|---|---|
| 落速 `NOTE_SPEED_PX_S` | 300 px/s | 判定线距底部 70px，屏幕高 450px，即音符从顶部落到判定线约 1.27s；这个值决定「预读时间」，改它只改一个宏 |
| 时间基准 | 进入 PLAYING 时的 `play_start_ms` | P0 无声，用系统毫秒计时；P1 改为音频进度（REQ-008） |
| 结束条件 | `judge_stat.judged == 音符总数` | 最后一个音符判完即进结算（REQ-005） |
| RESULT 超时 | 30s 无操作回 TITLE | 见下方状态机 |

**判定规则补充**（实现时确定、需求文档原本未写明的三条，2026-10-17 补记，供学生复核）：

| 规则 | 取值 | 理由 |
|---|---|---|
| 点击超出 ±120ms 时的处理 | **不判定也不消耗音符**（返回 `JUDGE_NONE`），由 `judge_tick` 在超时后判 MISS | 否则「提前乱点」会把后面的音符白白吃掉 |
| Acc 权重 | `acc = (perfect×100 + good×50) / judged`，存为百分比 ×100 的整数 | 与「命中率」直觉一致；权重是常量，产品上要调整只改 `judge.c` |
| 分数 | PERFECT +100、GOOD +50（P0 不设 Combo 倍数） | 规则简单、易手算（TC-004 要求分数与 Acc 与手算一致） |

场景状态机（REQ-001/005）：
| 当前状态 | 事件 | 下一状态 | 动作 |
|---|---|---|---|
| TITLE（主界面） | 点击「开始」区域（P0：屏上任意位置均可，主界面只有这一个可点元素） | PLAYING | 解析谱面、重置判定统计、记 `play_start_ms = 当前 ms`、**串口打印状态切换时间戳**（TC-001 要求） |
| PLAYING | 最后一个音符判定完 | RESULT | 冻结统计、计算 Acc、**串口打印结算四要素 + 状态时间戳** |
| PLAYING | （P0 不提供中途退出） | — | — |
| RESULT（结算） | 点击「重开」区域（P0：屏上任意位置） | PLAYING | 重置统计并重跑同一谱面（不重新解析，谱面已缓存） |
| RESULT | 超时 30s 无操作 | TITLE | 回到主界面 |

**输入分派与线程模型**：触摸事件只由读点线程写环形队列，**只有帧循环线程 pop**（单生产者单消费者，无锁），因此 `scene.c` 内部不需要互斥量。`scene_update()` 每帧把队列里积压的事件全部处理完，再调 `judge_tick(chart_ms)`。

**启动自检（REQ-007 / TC-007）的设计取舍**：

| 节 | 内容 | 为何放这个时机 |
|---|---|---|
| 1 谱面 | 先解析一份「故意错误」的谱面并确认被拒（必须**先**测，因为失败会清空 chart 的内部状态），再加载内置谱面并打印音符数、首/末时刻、轨道分布 | 启动时即可完成，不依赖任何运行期数据 |
| 2 判定 | `judge_selftest()` 的 12 个边界用例 + `judge_bulk_test(50)`，并打印判定延迟直方图与 P95 | 同上；直方图此时来自批量注入，真实演奏时会继续累加 |
| 3 帧率 | 读 `loop_stats()`，按 **CR-04** 判据（P95 ≤ 34ms）判 PASS/FAIL | **必须延迟到跑够 `SELFTEST_FRAME_WINDOW`（150 帧 ≈ 5s）之后**，否则样本太少、p95 无意义 |

**TC-007 「错误谱面时对应项显示 FAIL」如何演示**：`src/selftest.c` 顶部有编译开关 `SELFTEST_INJECT_BAD_CHART`，默认为 0（正常启动）；改成 1 重新编译后，第 1 节会拿错误谱面当内置谱面用，从而输出 `FAIL`。两种状态各留一次串口证据。

**与第 2 步的差别**：第 2 步用临时的 `input_bridge.c` 把触摸直接喂给 `judge_touch` 并打印；第 3 步由 `scene.c` 接管，`input_bridge.c` 删除。

## 6. 软件运行设计

- **RT-Thread 线程/定时器规划**

| 线程/定时器 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| `main`（初始化） | 中 | 4KB | 一次性 | 板级初始化 → `selftest_run()` → 进入 TITLE |
| `game_loop` | 中 | 8KB | 固定帧（16ms 或 33ms） | 读输入 → 更新 → 绘制 → `fb_swap()` |
| `touch_in` | 高于 game_loop | 4KB | 中断驱动 | 等信号量 → I2C 读点 → 打时间戳入队 |
| 1ms 软件定时器 | — | — | 1ms | 提供统一的 `now_ms()` 时间基准 |

- **同步与通信**：触摸中断 → 信号量 → `touch_in` 线程 → 环形队列（单生产者单消费者）；主循环非阻塞 pop。
- **时序与实时性**：关键路径 = 触摸中断 → 事件入队 → 下一帧判定；要求 ≤ 1 帧 + 队列延迟。帧循环每帧记录 `now_ms()`，用于帧间隔统计。

## 8. 非功能设计

- **性能（REQ-101）**：**采用整屏缓冲 + 每帧单次提交**（ADR-0003）。**M3 收口轮实测（统计口径修正后）**：**真实帧间隔** avg=33ms / p95=34ms / max=38ms / 掉帧 0；每帧处理耗时 work=31~32ms（其中 draw 2ms、flush 29ms）。结论：**按 CR-04 的 34ms 判据恰好通过，零余量**；主要开销是等 VSYNC（flush 29ms，与音符数基本无关），CPU 绘制余量很大但帧循环本身已无余地，因此判定/触摸/串口打印必须放独立线程。
  > 口径说明：M3 前几轮报的 `avg=28ms/p95=33ms` 是**每帧处理耗时**，会给人「还剩 5ms 余量」的错觉；收口轮已把 `loop_stats()` 拆成 `avg/p95/max_ms`（work）与 `avg/p95/max_interval_ms`（帧间隔）两组，判据一律用后者。详见 `docs/04` 的 L-11。
- 脏区更新（`fb_flush_rect()` 已预留）的收益上限约 5ms，但 flush 的 29ms 等 VSYNC 无法缩短，因此对帧间隔几乎没有帮助；是否实施取决于后续是否加入更重的绘制内容。
- **资源（REQ-102）**：帧缓冲 702KB 放 PSRAM；音符池固定上限（如 128 个）避免动态分配；打印 SRAM 静态占用并保留 ≥20% 余量。
- **可靠性（REQ-103）**：帧循环内不阻塞（I2C 读点在独立线程）；每 60s 打印 free heap；异常时 `rt_kprintf` 输出状态而非断言重启。
- **响应性（REQ-104）**：触摸中断即打时间戳，避免把 I2C 读点耗时算进判定误差；用 GPIO 打点 + 串口时间戳测量端到端延迟。
- **合规（REQ-105）**：所有音频/美术素材在 `docs/` 内附来源与许可说明；不含商业音游素材。
