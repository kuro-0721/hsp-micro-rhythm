# ADR-0005: 无马达——命中反馈由触觉震动改为音效（软件混音）

- 状态：已采纳
- 日期：2026-10-10
- 决策人：kuro-0721　协助：GitHub Copilot（DeepSeek V4.1 Flash）
- 关联需求：REQ-009（命中反馈）、REQ-008（音频通道）、`ADR-0004`（产品范围）

## 背景

REQ-009 原定"命中音符时触发马达震动（可开关）"。本板有马达驱动电路与预留焊点，但**马达需外购并自行焊接**（`docs/06` R-04、`docs/00` D-04），截至本决策日仍未采购；焊接又属于必须由人完成的物理验证环节。

学生判断：**"震动可以拿特殊音效代替，由于没有马达。"**

## 备选方案

| 方案 | 内容 | 优点 | 代价 | 影响 |
|---|---|---|---|---|
| A. 等马达到货再焊接 | 保留 REQ-009 原样，采购 + 焊接后实现 | 触觉反馈的打击感最好 | 依赖外部采购与焊接（agent 无法代做）；R-04 未到货，P1 有落空风险 | M4 可能整块延期 |
| **B. 音效反馈替代（采纳）** | REQ-009 改为"命中触发特殊音效"，用喇叭出声 | 不依赖采购；与"音游靠声音给反馈"的直觉一致；P1 本来就要做音频 | 打击感弱于震动；需与曲目 MP3 共存 | REQ-009 走需求变更 |
| C. 直接砍掉 REQ-009 | 不做命中反馈 | 最省时间 | P1 只剩"音画同步"，"打击反馈"这一维度完全缺失 | 需求缩水 |

### 子决策 1：音效与曲目如何共存（学生选 b）

| 选项 | 做法 | 代价 |
|---|---|---|
| a. 抢占式 | 命中瞬间短暂打断曲目解码，播完继续 | 实现最简单；可能有爆音/卡顿 |
| **b. 软件混音（采纳）** | 命中的短音效 PCM 与曲目解码 PCM 相加后送 I2S | 效果最好；需写混音 + 双缓冲，**估时 +8h** |
| c. 分区 | 仅 P0 无声模式下用音效，P1 放曲目时不给反馈 | 最省，但等于 P1 的打击反馈白做 |

### 子决策 2：判据必须保持客观（学生选 i）

原判据"命中时刻可在慢动作/示波器上看到马达驱动信号"是**客观可测量**的。改为音效后，若判据写成"能听到声音"就退化成主观感受，与本项目"用数据说话"的定位冲突。故采纳：

- **(i)** 命中时刻 **GPIO 打点 / 串口打印音效触发时间戳**，与判定时刻偏差 **≤ 20ms**（可复现、可复核）。

## 决策

采纳 **方案 B + 子决策 b + 子决策 i**，由学生（项目负责人）拍板：

1. REQ-009 由"命中触发马达震动（可开关）"改为"命中触发**特殊音效**反馈（可开关）"，涉及硬件由"马达"改为"喇叭"；
2. 实现方式为**软件混音**（音效 PCM 与曲目 PCM 相加后送 I2S），而非抢占式；
3. 验收判据改为客观时间戳比对（≤20ms），不使用"能否听到"这类主观判据；
4. 本项目**不再采购振动马达**（R-04 范围缩小为 TF 卡 + 电池）。

## 后果

- 正面：P1 不再依赖外购马达与焊接，去掉一个不可控的外部依赖；保留"打击反馈"这一维度；判据客观可复现。
- 负面 / 代价：**软件混音额外约 8h 工作量**，叠加在 R-06 的紧张进度上；混音运算占 CPU，而 M2 实测显示 30fps 下帧循环**只剩约 4ms 余量**，混音必须放在独立线程并注意优先级（已登记为 R-09）。
- 保留的可能性：若日后买到马达，可在此结构上追加触觉通道（音效与震动可以共存），不必重做。
- 需要同步修改：`docs/01`（§1.1、§3 REQ-009、§5、§9 变更记录）、`docs/02`（§2 架构图、§3 模块表、§5、§7、§9 风险、§10 验证计划）、`docs/03`（TC-009）、`docs/00`（T-09、D-04）、`docs/06`（R-04、R-06、新增 R-09）、`manifest.yaml`。

## AI协作

学生基于"没有马达"这一事实主动提出用音效替代，并选定软件混音与客观判据；agent 负责梳理三条共存方案的代价、指出"判据会退化成主观"这一风险并给出客观替代方案，以及登记派生风险 R-09。`ADR-0004` 中"P1 是否保留"的未决事项在本决策中一并关闭——P1 保留，但反馈形态改为音效。
