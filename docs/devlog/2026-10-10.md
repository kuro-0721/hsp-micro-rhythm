## 遇到的问题与解决

> 报错/卡点 → 排查过程 → 根因 → 解决办法。没有就写“无”。重要的问题同步登记到 `06-风险与问题台账.md`。

1. **pyyaml 显示安装成功但导入失败**。现象：安装动作返回成功，但终端里 `python -c "import yaml"` 报 `ModuleNotFoundError: No module named 'yaml'`，`setup_course.py` 也仍然提示未安装 pyyaml。排查：`Get-Command python -All` 看到终端实际用的是 Microsoft Store 版 Python 3.11.9（`...\WindowsApps\python.exe`），用它执行 `python -m pip show pyyaml` 显示 Package(s) not found。根因：上一次安装落到了另一个解释器环境里，两边不是同一个 Python。解决：显式对终端这个解释器安装 `python -m pip install --user "pyyaml>=6.0"`，再 `import yaml` 验证通过。教训：本机上「报装成功」≠「终端能用」，装完必须用同一条命令链验证。
2. **setup_course.py 报告 SiFli SDK 环境未就绪**：`SIFLI_SDK` 未设置、找不到 `scons`、找不到 `arm-none-eabi-gcc`。根因：执行初始化的这个终端没有运行过 SDK 的 `export.ps1`；SDK 实际已装在 `e:\tool\SiFli-SDK\v2.5.1`。脚本明确说明这不影响仓库初始化，因此本次未处理，留到 T0 B 部分在已 export 的终端里用 `python scripts/check_env.py` 复查。
3. **`check_all.py` 的 manifest 检查输出乱码**：终端按 GBK 解码脚本的 UTF-8 输出所致。后续在命令前加 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 后不再乱码。
4. **`export.ps1` 报 `uv was not found in PATH`**。现象：激活 SDK 失败，`check_env.py` 显示 SIFLI_SDK / scons / ARM 编译器全部缺失。排查：先确认工具链其实已装（`C:\Users\whf\.sifli\tools\arm-none-eabi-gcc\14.2.1`、`.sifli\envs\default\...`），再看 `export.ps1` 源码——它用 `uv run ... tools/sdk_env.py export` 生成环境脚本，没有 uv 就直接退出；只存在候选路径都没有 uv.exe。根因：uv 未全局安装，但 SiFli CodeKit 扩展自带一份（`...\globalStorage\sifli.sifli-sdk-codekit\uv\0.11.6\win32-x64`）。解决：把该目录临时加进当前终端 PATH 后 export 成功。**遗留**：仅本终端生效，新开终端需要重做（是否永久写入用户 PATH 待学生决定）。
5. **板载无 RESET 键**。现象：要求复位取启动横幅时，学生反馈板上没有 RESET 键。影响：复位只能拆插 USB；且必须**先建立串口监听再复位**，否则开机横幅在 1 秒内打完就丢了。解决：先 connect 再让拆插，成功抓到完整启动序列。
6. **监视器缓冲区会滚掉**：第一批真实数据是烧录后 59 秒的稳态输出（缓冲区只保留最近 60 条），启动横幅在此前已经滚出去；后续重新取证时又发现本次只拿到 20 条（id 16~35），因此启动日志窗口从 SDK 启动中期开始，不含 ROM/引导阶段。已如实写进 manifest 的 known_issues。
7. **证据文件被我自己写坏编码**。现象：用 `Add-Content` 追加烧录日志摘录后，中文变成 `����ɣ`。根因：漏写 `-Encoding utf8`，PS 5.1 默认用 ANSI 写盘，而文件头是 UTF-8。解决：删除重建，重写时显式 `-Encoding utf8`；错误与修复过程保留在本日志里。
8. **ffmpeg 抽帧时裁剪坐标算错两次**。现象：第一次按“最饱和像素”坐标换算出裁剪区，裁到的是桌面和线缆；第二次修正后又裁到透明塑料盒。根因：我把 160x90 缩略图坐标线性放大，但辉光是打在桌面的漫反射、不是灯珠本身，且画面里有其他常亮彩色物体干扰。解决：改成整帧缩小后拼成 4x3 九宫格，一眼看出绿→蓝→红循环。教训：先看整帧定位，再裁局部。
